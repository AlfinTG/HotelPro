# Demo Video and Skill Wallet Submission Checklist

## 1. Submission goal

The owner stated that the final course submission requires both:

1. the GitHub repository link; and
2. a demo video link entered in Skill Wallet.

Do not invent a course URL, upload destination, duration requirement or submission rubric that is not supplied. Confirm any limits from Skill Wallet before recording/uploading.

## 2. Before recording

- [ ] GitHub repository has application source code, not only planning documents.
- [ ] README setup instructions work from a clean checkout.
- [ ] Frontend and backend start without unresolved fatal errors.
- [ ] MongoDB connection works and demo data is ready.
- [ ] Demo admin account is provisioned through the documented safe method; credentials are not committed.
- [ ] Demo customer account can register/login.
- [ ] Rooms have usable descriptions/photos/prices.
- [ ] Customer booking and cancellation work against persisted data.
- [ ] Admin tabs load real records and Add Room persists a new room.
- [ ] Browser has no accidental personal data, secrets or unrelated tabs visible.
- [ ] The code version being demonstrated is the version pushed to GitHub.

## 3. Suggested short demo flow

Keep the video focused on the source-required features:

1. **Introduce the project:** HotelPro/Hotel Management and its purpose.
2. **Landing page:** show navigation, room highlights and About/room preview.
3. **Customer registration/login:** demonstrate form validation if useful, then enter the customer dashboard.
4. **Browse and book:** select a room, choose arrival/departure dates, confirm booking/payment simulation, and show the booking in My Bookings.
5. **Cancel:** cancel the eligible booking and show the changed status.
6. **Admin login:** show All Bookings, All Rooms, Add Room and All Users.
7. **Add a room:** submit the form and show the new room in the room list.
8. **Close:** briefly mention the technologies and repository location.

Do not show raw credentials or real payment data. If the app uses a simulated payment, say so explicitly rather than implying a real financial transaction occurred.

## 4. What to verify before sharing the video link

- Upload completed successfully.
- The link can be opened in a private/incognito browser or another account, if that is the intended evaluator access model.
- Audio is understandable and the relevant screens are visible.
- The video shows a working running app, not just screenshots of generated code.
- The GitHub repo URL is correct and contains the commit that matches the video.

## 5. Submit

- [ ] Paste the GitHub repository URL into the correct Skill Wallet field.
- [ ] Paste the accessible demo video URL into the correct Skill Wallet field.
- [ ] Complete any other required project fields shown by Skill Wallet.
- [ ] Capture/retain submission confirmation if available.

## 6. Final status language

Use exact status only:
- **Recorded:** a local video file exists.
- **Uploaded:** the hosting service confirms the file has uploaded.
- **Accessible:** the link was opened and verified with expected permissions.
- **Submitted:** Skill Wallet accepted/saved the links.

These are separate steps; never claim the later state based solely on an earlier one.
